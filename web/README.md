# بوابة لامين للحاسوب

واجهة ويب عربية RTL مضافة إلى المستودع نفسه، وتستخدم مشروع Supabase الحالي بدل إنشاء قاعدة مالية ثانية.

## الحالة والحدود
- تسجيل الدخول عبر Edge Function الحالية `auth-login` ثم جلسة Supabase.
- لوحة ملخص وقوائم للطلاب والمعلمين والصفوف والمبالغ المالية، مع الاعتماد على RLS في قاعدة البيانات.
- تصدير CSV لقائمة الطلاب.
- نسخة JSON عبر RPC الحالية `export_backup`، مع التحقق من أن `school_filter` يطابق المدرسة النشطة.
- فحص ملف النسخة قبل الاستعادة، وطلب تأكيد نصي، ثم استدعاء RPC `restore_backup` الحالية.
- لا تُنفّذ الواجهة أي ترحيل قاعدة بيانات ولا تغيّر إعدادات الإنتاج.
- لا تُعدّ الواجهة منشورة أو معتمدة للإنتاج قبل اختبارات تكامل حقيقية لحسابات المدارس وRLS والنسخ والاستعادة.

## تشغيل محلي
قدّم مجلد `web/` عبر خادم ملفات ثابت يدعم HTTPS في النشر. يستخدم `app.js` المفتاح publishable المخصص للعميل؛ لا تضع مفاتيح service-role أو أسرارًا في ملفات الويب. المصادقة والتفويض النهائيان مسؤولية Supabase Edge Functions وRLS وإجراءات RPC.

## نقاط تحقق قبل الإطلاق
1. التأكد من أن `auth-login` يعيد `access_token` و`refresh_token` لهذا التدفق.
2. اختبار دور `owner` ودور `admin` ودور غير إداري على مدارس تجريبية منفصلة.
3. التحقق من تطابق شكل ناتج `export_backup` مع تنسيق النسخة V2 الحالي.
4. اختبار استعادة نسخة صحيحة، ورفض ملف مدرسة أخرى وملف تالف، في قاعدة تجريبية معزولة فقط.
5. اختبار التقارير والأرصدة مع بيانات تجريبية قبل السماح بعمليات مالية إضافية.
